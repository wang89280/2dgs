# 稳健三角化：同一工程内的可选后端

前端仍为原 ALIKED-N32 + LightGlue。新模块由独立 C++ 实现，不调用 Metashape 或 COLMAP mapper；COLMAP 仅在参考实验里使用。默认 `off`，原因是目前证据支持未筛选轨迹的三角化尾部误差改善，尚未证明整套 SfM、稠密模型或 2DGS 的提升。

## 处理新图片

```powershell
./run.ps1 -Images 'F:/path/to/images' -SparseOnly -PointRefinement robust
# Python 同义开关
python run_pipeline.py --images 'F:/path/to/images' --sparse-only --point-refinement robust
```

流程为原有 SfM → 轨迹维护 → 可选图像精化 → 可选稳健三角化 → 稀疏输出。图像精化默认关闭。稳健三角化只重新求每条轨迹的 XYZ，相机位姿、内参、原始 UV、轨迹编号、点数和观测数保留；失败点保留原坐标。复用一个已有模型，无需重新提取或匹配：

```powershell
python code/sfm/point_refinement_stage.py --source 'F:/已有模型根目录' --output 'F:/新的模型根目录'
```

源目录应包含 `sfm/calibration.bin`、`poses.bin`、`camera_ids.bin`、`points.bin`、`active_points.bin`、`observations.bin`、`cameras.xml` 和 `summary.json`，输出目录必须不存在。生成 `sparse.ply`、完整原生 SfM 文件与 `point_refinement.json` 审计。没有调用任何 2DGS 训练。

## 改了什么

旧模块：有限两视图假设 → 4px 硬内点集合 → 集合内 L2 拟合。新模块：全射线交会、旧模块结果与最多 64 对确定性两视图初值 → 选取目标最低的 4 个初值 → 对全部观测优化径向 Cauchy 损失 `2*log(1+||e||²/4)` → 正深度与 1.5° 三角化角检查。最多 40 次阻尼优化，代价不下降则拒绝该步。

这是已有稳健估计思想在本工程中的实现与组合，不是声称发明 Cauchy 损失。新模块仍依赖原 SfM 建立的轨迹对应关系，不能修复占多数的错误对应，也没有利用测试视角坐标选择三维点。

## 实验与限制

完整证据见 [后端报告](../outputs/sfm_backend_diagnosis_20261014/SfM后端瓶颈与改进报告.md)。其中同时保留三个比较：

1. 原来的 `prediction.py` 相机主指标，完全不改评价算法；未见明显涨点。
2. 相机固定、锚点和查询固定，直接比较旧原生三角化、新三角化、COLMAP LO-RANSAC 三角化；新模块降低大误差尾部约 7%，但 3px 命中率并非全面上升。
3. 与历史评价器自带的 DLT + soft-L1 点估计比较，优势不明显。不能选择性隐去这一对照。

本轮复用既有场景与特征留出划分，不是新场景盲测。全数据点云自身 RMSE 略升，因为优化目标从 L2/Huber 转为更强调抗异常值的 Cauchy；不能用该数值证明绝对三维精度。没有独立几何真值，也没有新增稠密或 2DGS 训练。
