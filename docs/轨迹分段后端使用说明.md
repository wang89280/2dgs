# 轨迹分段后端：实验候选

代码：`code/sfm/python/ordered_track_partition.py`；完整模型入口：`code/sfm/track_lifecycle_stage.py`。
ALIKED-N32、LightGlue、原始特征坐标、匹配缓存、相机和内参保持不变。本模块依赖 NumPy/SciPy，不调用 Metashape；PixSfM 是另一个独立对照，不是这个模块的依赖。

## 算法

1. 按原图编号整理一个轨迹的观测。至少 8 个视角才考虑拆分。
2. 用 DLT + soft-L1（2px）估计单点解释，与原强三角化基线一致。
3. 在约 1/3、1/2、2/3 处尝试拆分；每段至少 4 个视角、三角化夹角至少 2°。
4. 要求两段的总平方误差至少下降 50%，并超过固定复杂度惩罚 `1.5² × [3 log(2N) + 2 log(3)]`。
5. 在该轨迹内部做两折交替视角交叉验证；两段的预测平方误差还必须下降至少 25%。
6. 通过后输出两个三维点；原始观测不删除、不复制、不移动像素，只更新其中一段的点归属。记录父子轨迹映射。不通过则保留原轨迹。

上述阈值在四组运行中相同，没有按数据组分别选参数。每条父轨迹最多产生一个子轨迹，不递归增加自由度。

## 运行

在工程根目录，使用已经装好 NumPy/SciPy 的 Python：

```powershell
python code/sfm/track_lifecycle_stage.py --input '已有模型根目录' --output '新的输出目录'
```

输入根目录须含本工程的 `sfm/` 文件。输出必须为新目录，包含 `sfm/`、`sparse.ply`、`metrics.json`、`partitions.json` 和 `track_lifecycle.json`。完整成功结果会跳过；中断的半成品会拒绝覆盖，换新输出目录或先检查现场。

现有默认流水线未自动启用此实验模块。完整四组结果在 `outputs/featuremetric_backend_20261014/<数据组>/full_track_lifecycle/`。

严格的模块预测消融：

```powershell
python tools/run_anchor_track_split.py --datasets 1-1 2-1 3-1 4-1
python tools/test_track_lifecycle.py
```

相机固定为强基线，测试轨迹的交替一半视角用于拟合和内部交叉验证，另一半视角只评分。查询视角由图像编号选择落在哪一段，查询像素坐标不参与段选择。全部原始查询均保留，失败按 20px 计分。强基线是同一批查询上的 DLT + soft-L1，不是较弱的旧硬阈值三角化。

## 结果的含义与限制

详见 `outputs/featuremetric_backend_20261014/后端实验报告.md`。模块留出收益不等同于相机精度、全模型表面精度或 2DGS 提升；全模型自身 RMSE 单独列出。重复使用了这些场景的留出集，尚无新的盲测场景。

本算法依赖拍摄顺序。若图片编号随机、多个不连续拍摄序列混排，或旋转闭环跨越编号首尾，线性分段可能失败。前景轮廓随视角变化，即使分段后投影误差更小，也不能证明每段对应同一真实表面点。不得据此声称毫米精度、99% 接近原厂或全新学术算法。

## PixSfM 对照环境

`tools/run_featuremetric_experiment.py` 在 Windows 调度 WSL Ubuntu-20.04 中的 PixSfM；该分支需要本机现有编译环境，运行时路径在 `code/sfm/third_party/pixsfm_backend/PROVENANCE.json`，并非可跨机器直接运行的独立软件包。算法来源为 [PixSfM](https://github.com/cvg/pixel-perfect-sfm)，有独立许可证。

官方原版 S2DNet 权重链接本次不可用，实验显式使用已发布 DenseSfM 权重中的 S2DNet 架构骨干，并额外跑 VGG16 ImageNet 对照。没有将这一配置称为原版 PixSfM 完整复现。只启用 SfM 之后的 BA，关闭其关键点调整阶段。缓存放在 WSL 的 `seed_featuremetric_backend_20261014/cache`，可从哈希一致的图片重建。
