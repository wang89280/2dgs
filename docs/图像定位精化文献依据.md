# 图像定位精化的文献依据与主张边界

核验日期：2026-10-14。结构化来源登记见同目录 `research_image_refinement_20261014.json`。其中 `verified` 表示已核对文献身份、官方来源和相应证据位置，不表示本工程已经复现该论文或达到其结果。下述方案不能保证涨点，实际效果应以冻结评估协议后的实验为准。

当前方向是补充跨视图图像测量信息。轨迹重组能够改变已有观测的组织，却不能自动纠正特征定位偏差。现有消融尚不足以确定定位误差是主导瓶颈，因此需要验证该方向，而不能先把它写成有效结论。

## ALIKED 已经具有亚像素坐标

Xiaoming Zhao、Xingming Wu、Weihai Chen、Peter C. Y. Chen、Qingsong Xu、Zhengguo Li 的 *ALIKED: A Lighter Keypoint and Descriptor Extraction Network via Deformable Transformation*，2023，IEEE Transactions on Instrumentation and Measurement，身份可由[作者论文页面](https://arxiv.org/abs/2304.03608)核对。

[官方 `DKD.detect_keypoints`](https://raw.githubusercontent.com/Shiaoming/ALIKED/main/nets/soft_detect.py) 默认使用 `sub_pixel=True`，在局部响应图上计算 SoftArgMax 偏移。因此不能说 ALIKED 仅输出整像素，也不能把新增模块描述为“首次给 ALIKED 增加亚像素”。准确表述是：**在原有亚像素检测坐标上，利用跨视图图像证据进一步精化定位。** 输出浮点坐标也不等于具有经过真值验证的亚像素精度。

## 本工程可以实现和检验的内容

候选流程是：从原始匹配位置出发，以受限局部图像对齐获得位移建议，检查前后向和多视图一致性，按 `(image, feature_id)` 融合成唯一观测坐标，再交给固定内参的独立 SfM 后端。图像证据不足时保留原坐标，并记录拒绝原因。不能直接把点投影回当前相机作为“像素精化”，因为那会把模型预测当成测量，造成虚假的残差降低。

这种 KLT、图联合和后端优化的集成是工程近似，**不是完整 PixSfM、PatchFlow 或 Keypt2Subpx 复现**。已有论文提出的特征度量优化、局部对齐、亚像素预测等不能主张为本工程原创。可以检验的工程贡献包括多视图位移融合、特征身份一致性、位移约束、失败回退、独立后端接入及可审计消融。是否达到研究层面的创新还需进一步查重和实验支持。

如果另外加入图像可信度加权，应与定位精化分开消融。梯度、局部 Hessian、前后向误差和多锚点分歧只是可能的可信度代理；未经真值校准，不应把这些量称为准确的概率协方差，也不能保证加入权重必然优于等权 BA。

## 评估必须保留的边界

- 测试特征不得参与位移估计、参数选择或 BA；测试查询坐标保持冻结的原始测量。
- 对比要记录相同内参、特征身份、像素位移、观测保留率、失败率与运行成本，不能只看自身观测 RMSE。
- 需要区分自身拟合残差、共同观测残差和留出预测误差；定位、图融合及可选加权应能分别关闭。
- 已反复查看的旧 holdout 只能提供开发证据；最终泛化结论需要未参与方法选择的新数据或独立真值。
- 无独立几何真值时，不声明毫米绝对精度、不声明达到 Metashape 的 99%，也不保证“明显涨点”。

本文是文献与候选方案的依据记录，不是实验完成报告。具体实现是否启用、接受了哪些改动及真实效果，以对应代码、运行日志和实验报告为准。

## 2026-10-14：官方 Keypt2Subpx 推理适配

另一个开发候选已接入原作者的 ALIKED 预训练 refiner，保留默认关闭。它直接使用官方 `AttnTuner(128, use_score=True)`、原始权重和配对描述子均值运算，没有用经典 LK 或任意局部 crop 代替学习模块。来源锁定到 Keypt2Subpx commit `30598aeb3c7676cb1459248d780562bfc0e604a2`；所下载原文件未修改，许可证为 Apache-2.0。各文件的 URL、字节数、SHA256 与 Git blob 校验见 [SOURCE_MANIFEST.json](/F:/03_matlab_python/352_seed_3dgs/code/00_colmap/03_meatshape_cpp/release/V9_SfM_2DGS_Complete_20261012/code/sfm/third_party/keypt2subpx/SOURCE_MANIFEST.json)。权重共 1,485,078 字节，SHA256 为 `81ddf265390b7afa9670f0ef7dabee0a43307f465aa98ce6595fa78a2c475ab7`。

适配器接收 `(N,128)` 原描述子和两种 `(N,1,11,11)` patch：RGB 按 `[0.299,0.587,0.114]` 转灰度的原图 patch，以及未经再次归一化的 dense Sigmoid score-map patch。配对描述子取算术均值后不再次归一化；网络输出乘 `2.5`。原 tile 来源、原 normalized keypoint 和前端特征 ID 必须保持一致，不能以稀疏检测分数代替完整 score map。patch 采用官方 5px 零 padding、整数截断、边界 clamp 及整数采样。接口和验证记录见 [接入说明](/F:/03_matlab_python/352_seed_3dgs/code/00_colmap/03_meatshape_cpp/release/V9_SfM_2DGS_Complete_20261012/code/sfm/third_party/keypt2subpx/INTEGRATION.md) 与 [推理接线验证](/F:/03_matlab_python/352_seed_3dgs/code/00_colmap/03_meatshape_cpp/release/V9_SfM_2DGS_Complete_20261012/code/sfm/third_party/keypt2subpx/INFERENCE_VALIDATION.json)。

官方 Keypt2Subpx 绑定的 GlueFactory commit 是 `4a8283517fb77e7527e278e233df502f8b7a3266`。[该版本 ALIKED 源码](https://github.com/cvg/glue-factory/blob/4a8283517fb77e7527e278e233df502f8b7a3266/gluefactory/models/extractors/aliked.py) 中，DKD 按 `[w-1,h-1]` 归一化，但 `_forward` 用 `wh * (torch.stack(keypoints) + 1) / 2.0` 恢复，其中 `wh=[w,h]`。当前工程 ONNX 前端则恢复为 `(normalized+1)*[w-1,h-1]/2+0.5`。对于各特征所属原 tile，二者转换为：

```text
official_xy = (tile_native_xy - 0.5) * [w/(w-1), h/(h-1)]
native_offset = official_offset * [(w-1)/w, (h-1)/h]
```

实现优先从保留的原 ONNX normalized 输出按官方 float32 运算顺序恢复坐标，避免 native 往返转换的舍入导致整数 patch 索引改变。native 偏移加回全图原 native 坐标；tile 原点仅用于追溯，不能随精化重复叠加。

**这是 N16→N32 的迁移适配，不是论文配置完整复现。** 官方数据准备使用上述 GlueFactory ALIKED 默认配置 `aliked-n16`，当前工程使用 `aliked-n32.onnx`。二者描述子都是 128 维，并不证明描述子基、score-map 分布或预训练 refiner 的适用性相同。当前 tile 化提取、多视图建议融合和独立 SfM 后端也属于本工程的配置；不能用“调用了官方网络”代替整条论文流程的等价性说明。

已完成的是数值接线验证：Windows PyTorch `2.6.0+cu124` 上安全加载官方权重并执行 CUDA 推理；8 对包含边界的合成样例与官方完整 `Keypt2Subpx.forward` 的 native 坐标最大差为 `7.63e-6` px。这个数值只衡量两个实现调用的等价程度，**不是定位误差、三维精度或真实数据的提升幅度**。后续开发集结果应另行记录；本文不预写收益结论，也不据此启用默认开关。
